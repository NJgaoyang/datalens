## 1. 产品方向

DataLens 定位为“企业内部多人使用的智能数据分析工作区”。参考 Chat2DB 将数据库上下文、SQL、AI 助手和结果组织到同一个工作区的方式，但不复制成通用数据库管理客户端，也不继续把技术模块逐个暴露为业务用户的菜单。

主流程：

```text
进入分析空间 → 直接描述问题 → 必要时澄清
→ 生成受控查询 → 展示表格/图表与口径
→ 继续追问调整 → 确认保存
→ 每次打开重新查询 → 私有/指定用户/全员共享
```

本提案采用“问数优先，SQL 辅助”的默认入口。分析人员仍有 SQL 工作区，但普通用户不必先填写 SQL、参数 JSON、会话名称或图表字段名。

### 已确认、继续保留的约束

- 独立项目；后端保持 Java 21 / Spring Boot，前端保持 Vue 3 / TypeScript / ECharts，不因为参考项目而整体换技术栈。
- MySQL 8 保存系统元数据、账号、会话、权限、查询定义和图表；外接 StarRocks 执行分析查询，两类连接池分离。
- Linux 原生运行；不用 Docker、Nginx，暂不用 Redis。单 JAR 同时提供前端和 API，通过 IP+端口访问。
- 保留 `package.sh` 生成 tar.gz、`conf/` 配置、`bin/` 启停的交付方式；保留已有 Node 22/24 打包支持。运行机器不要求安装 Node。
- 用户确认后才保存正式图表；图表保存的是查询定义、时间规则和图表配置，不是截图，也不依赖模型在线。
- 私有、指定用户、系统全员共享；全员仅指有效登录账号。普通共享者只读，超管可管理所有图表并记录真实操作人。
- 不读取、清空或迁移生产数据；不删除原分支，不合并至 main。

本文的视觉尺寸、菜单合并和新增问数模式属于此次设计建议，不应写成用户已逐项确认的要求。旧文档中 Docker/Redis 等历史说明不得覆盖上述已经确认的原生部署约束；具体运行参数仍以现有原生配置和部署文档为准。

## 2. 当前实现与目标的主要差距

| 当前代码中可观察到的情况 | 重设计目标 |
| --- | --- |
| `App.vue` 同时展示业务主题、业务语义、安全 SQL、问数和多种图表范围，系统配置也分散在侧栏 | 日常操作收敛为智能问数、图表中心、SQL 工作区，管理员配置进入独立管理区域 |
| `ConversationView.vue` 先选择主题、填写标题、创建会话，再输入问题 | 首屏直接输入问题；一个授权空间时自动选中，多个时明确选择；标题可从首问生成并允许改名 |
| `ConversationService.definition()` 直接取已发布指标的 `m.sql()`；常见流程是让模型选择审核指标 | 新增基于授权表结构生成查询的路径，同时保留已审核口径的优先级和现有安全查询边界 |
| 当前追问对“改成上个月”有显式分支，其他问法仍围绕已审核指标选择 | 支持结构化修改时间、分组维度、筛选、排序和 Top N，而不是仅匹配几个固定短语 |
| 图表编辑暴露 SQL、参数 JSON、英文图表类型、日期参数索引 | 普通保存弹窗只呈现名称、图表类型、口径、时间规则；高级查询细节按权限展开 |
| 图表范围、后台配置与用户任务之间存在较多页面跳转 | 查询、表格、图表和保存围绕同一次结果完成，管理与使用分开 |

上述差距是基于基线源码的评审判断，不是对实际用户行为的测量，也不代表已进行真实模型或 StarRocks 联调。

| 参考内容 | DataLens 的采用方式 |

## 4. 信息架构与页面设计

### 4.1 全局结构

```text
DataLens
├─ 智能问数（默认入口）
│  ├─ 新建分析
│  ├─ 我的历史会话
│  └─ 当前分析空间 / 可用表与字段
├─ 图表中心
│  ├─ 我的图表
│  ├─ 共享给我
│  └─ 全员共享
├─ SQL 工作区（已有数据查询权限的用户）
│  ├─ 授权数据资源树
│  ├─ 查询标签 / 已保存查询 / 执行历史
│  └─ SQL 编辑器 / 数据结果 / 图表 / AI 助手
└─ 管理中心（超管）
   ├─ 数据源与元数据
   ├─ 分析空间与数据授权
   ├─ 业务口径与字段说明
   ├─ 模型配置
   ├─ 用户管理 / 全部图表
   └─ 审计与系统状态
```

管理入口放侧栏底部。账号菜单保持修改密码、退出登录；不重复堆叠角色文字。系统状态不再是普通用户的首页。原有图表详情地址继续可达，旧入口可重定向，不通过删除接口实现导航收敛。

### 4.2 智能问数主界面

```text
┌───────────────────────────────────────────────────────────────────┐
│ DataLens    智能问数                 当前分析空间          账号    │
├──────┬─────────────────┬──────────────────────────────────────────┤
│导航  │ ＋ 新建分析      │ 当前会话                                  │
│      │                 │                                           │
│问数  │ 历史会话         │ 用户：最近 30 天，每个城市的订单金额是多少？│
│图表  │ ……              │                                           │
│SQL   │                 │ 查询口径 · 时间范围 · 查询状态             │
│      │ 当前空间         │ ┌──────────────────────────────────────┐ │
│      │ 表 / 字段说明    │ │ 数据表格 | 图表 | 查询说明 | SQL*      │ │
│      │ （可收起）       │ │ 同一次查询的真实结果                   │ │
│      │                 │ └──────────────────────────────────────┘ │
│      │                 │ 调整图表                  确认保存图表   │
│      │                 ├──────────────────────────────────────────┤
│设置  │                 │ 继续提问……                        发送   │
└──────┴─────────────────┴──────────────────────────────────────────┘
```

`SQL*`：仅对有原始查询访问权的用户显示；只读共享图表的接收者不得因此获得 SQL、源表结构或自由查询能力。示例问题仅解释设计，不是系统已接入的真实业务表。

首屏行为：有授权空间时直接输入；无空间时展示真实的无权限/未配置状态，不显示伪业务数据。首问提交内部完成会话创建和轮次提交，并使用幂等键；创建成功但发送失败要能重试同一会话，不能创建重复会话或丢失输入。中文输入法组合输入期间不触发 Enter 提交；Enter 发送、Shift+Enter 换行，均需提供可点击按钮。

结果行为：默认用适合结果结构的表格或图表展示；表格有横向滚动、列宽调整和空值说明。切换展示类型不重新请求模型；只有改变筛选、时间、指标或排序等查询语义时才执行新查询。大数值和金额保持后端精度，不在浏览器对截断明细二次汇总成“总额”。

### 4.3 SQL 工作区

采用“左侧授权资源树 + 中央查询标签/编辑器 + 下方结果 + 可折叠右侧 AI 助手”的结构。工具栏围绕执行、停止、格式化、保存查询、转换为图表组织，不提供数据库写操作。

每个标签拥有独立的查询文本、选定分析空间、任务 ID、结果和运行状态。切换标签不能把旧请求结果写入新标签；关闭正在运行的标签需明确取消策略，不能仅关界面便宣称数据库已停止。保存 SQL 草稿与保存动态图表是不同操作。

### 4.4 图表中心与保存/共享

图表中心用“我的 / 共享给我 / 全员共享”页签，支持名称搜索和类型/更新时间等适用筛选。列表只读取已授权元数据，不为每个卡片批量运行 SQL；未经真实刷新取得的结果不能绘制成假缩略图。

保存弹窗展示：名称、展示类型、已确认指标说明、时间规则和默认私有提示。先预览再确认保存；修改查询后旧预览立即失效。保存行为绑定明确的查询版本和结果，不保存聊天文字或模型临时响应作为执行依据。

共享在保存后单独设置：仅自己、指定有效账号、全员。选择指定用户才显示用户选择器；共享页说明接收者只能查看已发布图表。撤销共享后旧链接、任务结果和下载都重新鉴权。普通共享者不能编辑、再共享、转移所有权或提交任意 SQL；导出仍使用独立授权。

图表详情打开后执行保存的查询定义，标明本次查询完成时间、时间范围和上次成功时间。模型关闭时仍能刷新。刷新失败明确显示失败；如保留上次结果，必须标为历史结果。相对时间按保存的业务时区重新计算；固定日期保持固定，不允许混淆。

### 4.5 视觉与交互建议

首版建议浅色：白色内容区、浅灰侧栏、细分隔线、少量蓝色强调、统一线性图标，无大面积渐变和装饰性统计卡片。参考的是工作区组织方式，不是复制 Chat2DB 的商标、图标或固定配色。

建议导航栏约 56px；资源/历史区约 240px，可在 200–360px 范围调整并收起；顶栏约 48px；正文 14px、辅助文字 12px、编辑器 13–14px。只在 SQL 模式按需展开右侧助手，避免普通问数页同时挤入四个常驻面板。

在 1440/1920 桌面宽度验收；窄屏将资源栏和助手变成抽屉，不压缩结果表格到不可读。面板分隔条支持键盘调节与可见焦点；收起后必须保留明确的展开入口。所有图标按钮有可访问名称。

## 5. 问数能力：从指标选择器到受控查询生成

### 5.1 保留审核口径，新增结构辅助模式

现有已审核指标路径继续可用，不删除指标审核和权限校验。设计上新增 `SCHEMA_ASSISTED` 路径，由管理员对分析空间显式启用；原有空间默认保留原行为，不能一次部署就放开所有 SQL。

新路径允许在授权的单表或经过治理的视图上，根据字段类型、备注、业务别名和已知口径生成不同的筛选、聚合、排序和分组，不要求每一个问题都预先保存一条完整 SQL。

已发布且匹配的业务指标优先使用；仅凭字段结构不能推断清楚的“收入”“有效订单”等业务概念先澄清。基础探索结果必须标明口径来源，不能把模型提议标成已审核指标。

第一批真实验收限定单表/治理视图。跨表分析须另增已审核关系、连接粒度和防重复累计规则，再扩展 SQL 解析与权限测试；在此之前明确提示不支持，而不是偷偷允许任意 JOIN。

### 5.2 执行链路

```text
服务端认证与当前授权范围
  → 读取该范围内的元数据/已发布口径
  → 整理当前用户当前会话的结构化上下文
  → 模型提出 QueryIntent / QueryPlan / ChartSpec
  → 服务端校验 SQL AST、对象/函数白名单、参数和预算
  → 原有 QueryService 执行只读查询
  → 结果返回前再次鉴权
  → 生成可预览结果
  → 用户确认后交给 ChartService 保存
```

模型返回内容一律不可信；不能直连数据库、不能绕过 QueryService、不能使用关键词过滤替代 AST。凭据、隐藏字段、其他用户会话、完整数据库样本和任意工具执行权限均不进入模型上下文。是否向外部模型发送结果摘要应成为显式、受控的数据策略，首版默认不发送结果行。

权限快照用于追踪，不是永久授权凭证。生成、执行、取结果、保存和共享各节点均复查当前权限。新生成查询的来源证据应区分 `REVIEWED_METRIC` 与 `SCHEMA_ASSISTED`，不得伪造旧的 `SemanticBinding` 来绕过其审核边界。

### 5.3 多轮追问

服务端保存并版本化指标、维度、筛选、时间、排序、Top N 和图表配置。追问是对该结构的受控修改，不是把所有聊天记录拼接后任模型执行。

目标示例：

```text
最近 30 天各城市的订单金额
→ 改为按天看
→ 只看上海
→ 与上个月比较
→ 显示为折线图
```

前三类查询语义变化重新生成计划并校验执行；只改变图表类型时复用仍有效的结果。比较周期需要明确是上个完整自然月还是等长前一周期；没有明确口径先澄清。不把示例当成当前已经支持的功能。

处理状态只显示真实阶段：理解问题、待澄清、校验查询、排队/查询中、结果可用、无数据、失败、已取消/取消未确认。不展示伪推理过程、虚假百分比或未证实的数据库取消成功。有限修复必须受次数/时间预算约束，并对每次修复后的查询重新完整校验。

### 需要改造

### API 与数据库原则

D00 **无 API 或 schema 变更**。D01 尽可能复用现有会话、查询、图表接口。涉及首问连续提交时要处理幂等、重试和乐观版本，不能以客户端身份字段确定操作人。

后续 D02/D03 如新增计划预览/执行、结构化上下文或来源字段，必须先更新 `contracts/`，定义请求、响应、错误码、版本冲突和撤权行为，并用新增 Flyway 迁移实现。API 名称、表名与字段应在实施时形成单独可审查的合同，本文不把尚未实现的端点当成现有接口。

| D05 原生交付回归 | Java 单 JAR、MySQL 8、外接 StarRocks、tar 包与启停回归 | D01–D04 | 构建、单元、浏览器、真实 MySQL 集成及原生包验证有证据；真实业务正确性独立验收 |

首批关键验收场景：

1. 无数据源/模型时可启动，页面给出真实引导，不伪造查询成功。
2. 有一个授权空间时直接问数，无需先创建标题；失败重试不产生重复会话和轮次。
3. A/B 同时使用同一个模型服务，无法看见对方会话、未共享图表或任务结果。
4. 未授权表/列不出现在资源树、模型上下文和结果；模型提出越权查询也被服务端拒绝。
5. 一次结果切换表格/图表不重跑模型；改变查询条件后旧预览不能继续保存。
6. 业务定义不清、跨表关系未审核或方言不支持时明确澄清/拒绝，不返回编造数据。
7. 确认保存前不生成正式资产；保存后关闭模型仍能刷新当前数据。
8. 相对时间每次按业务时区计算；固定时间不随打开日期变化。
9. 指定共享只对被选用户生效；全员共享拒绝匿名；查看不自动获得自由 SQL 或导出权限。
10. 执行中撤权、禁用账号或撤销数据源范围后，旧任务和下载无法继续取回结果。
11. 刷新失败、截断、无数据、超时、取消未确认均有准确状态；不把旧数据冒充本次结果。
12. 新旧数据库启动、打包与 bin 启停按实际环境验证，不把 mock/浏览器夹具当成真实 StarRocks 验收。

每次提交报告必须分列已执行通过、失败、未执行及原因。仅修改文档时不声称应用构建或运行通过。
