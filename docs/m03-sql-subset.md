# M03 SQL compiler boundary

`SafeSql.validate(sql, allowedColumns, parameters)` parses with pinned JSQLParser 5.3 and emits a new SQL string exclusively from supported AST nodes. It never executes the submitted string or generic AST rendering. `Validated` contains canonical SQL, physical referenced fields and placeholder count. `QueryParameters` independently validates and binds typed values. Traversal order is not binding order: placeholders are emitted in the original textual SQL order, preserving CTE, SELECT, FROM/JOIN and WHERE positions. The compiler never interpolates parameter values.

Supported: one SELECT; explicit authorized columns; INNER/LEFT/RIGHT JOIN with one ON clause; non-recursive SELECT CTEs; named derived tables; uncorrelated scalar/IN subqueries with one named output; arithmetic and comparison operators; AND/OR; IS [NOT] NULL; [NOT] BETWEEN/IN; DISTINCT; GROUP BY/HAVING; ORDER BY including output aliases; positive literal LIMIT <=100000. The executor imposes its stricter independent result limit. Identifiers use ASCII letters/digits/underscore, at most 64 characters, optionally backtick quoted. Table/catalog/database selection comes solely from the administrator-controlled connection: SQL-qualified catalog/database names are rejected.

Function allowlist: COUNT, SUM, AVG, MIN, MAX, ABS, ROUND, FLOOR, CEIL, COALESCE, NULLIF, LOWER, UPPER, LENGTH. Functions require explicit arguments. Wildcards, including COUNT(*), are unsupported; use COUNT(authorized_column), respecting its NULL semantics. At least one authorized physical field must be referenced. String/date values must use typed bound `?` parameters. Numeric SQL literals and NULL are supported. Expression results used by derived tables/CTEs require explicit unique output aliases.

Intentionally rejected: writes, DDL, multiple statements, SELECT INTO, OUTFILE, locks, all wildcard projections, qualified/UDF functions, system variables, table-valued/external functions, correlated/recursive queries, UNION/set operations, windows, CASE/CAST, vendor hints and clauses, offset/pagination extensions, comments, backslashes, named/indexed parameters and any unknown AST node/property. Unsupported syntax must be extended with dedicated authorization and dialect tests; there is no keyword-based fallback.

Non-consumed AST properties must equal their pinned parser defaults. This guards hidden dialect attributes, while the compiler emits only fixed operators and validated identifiers. Parser upgrades require reviewing this boundary and rerunning the attack suite. Limits: 16000 SQL characters, nesting precheck <=24, semantic SELECT nesting <=12, AST work <=1000 nodes, <=100 projections/parameters/list arguments, and parser timeout 1000 ms. Comments/backslashes are rejection-only guards, not authorization.

Validation evidence: 88 JUnit tests pass locally against JSQLParser 5.3 and the cached Java 21 application classpath. Includes 80 rejection cases, nested-object authorization, canonical reparse stability, CTE/SELECT/JOIN placeholder order, hostile bound values, and 60 concurrent compilations alternating distinct allowed-column scopes. This is parser/unit evidence only. Real StarRocks 3.3.22 syntax, TLS connectivity, JDBC cancellation and server timeout verification remain pending and are not established by these tests.
