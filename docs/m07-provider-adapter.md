# M07 provider transport security and operational limits

`ModelTransport` isolates the OpenAI-compatible, non-streaming HTTPS chat-completion protocol. Construction and application startup perform no provider request. Tests inject a fake sender; no test sends real credentials or contacts a model provider.

`DATALENS_MODEL_ALLOWED_ENDPOINTS` is a comma-separated set of exact complete HTTPS completion URLs. The default empty set denies every endpoint. Configuration saving and every outgoing request both validate the policy. Only canonical **public numeric IPv4** destinations are supported. Hostnames, all IPv6 addresses, private/loopback/link-local/shared/multicast/reserved/documentation networks, URL credentials, query strings, fragments, encoded paths and dot segments are rejected even when allowlisted. The path must consist of ASCII letters, digits, slash, underscore or hyphen. Ports are optional or 1–65535. No DNS lookup occurs, so a hostname cannot rebind between validation and connection. This deliberately conservative policy is not a general-purpose Internet URL validator.

Deployment requires an operator-controlled HTTPS model gateway with a public IPv4 address and a trusted certificate containing that exact IP in its IP subject alternative name. The JDK's ordinary trust-chain and endpoint verification remain enabled. Direct `api.openai.com` and other hostname provider endpoints are intentionally unsupported in this milestone. Do not work around this by disabling TLS verification, weakening endpoint policy, or using self-signed trust bypasses. An alternative hostname-pinning transport would require separate security design and tests before broadening support. Endpoint allowlisting alone is not proof that an operator-selected gateway is trustworthy.

The client disables redirects and system proxies. It sends one request, with no transport retries and no streaming or tools. The response subscriber caps incoming data at 128 KiB and cancels on overflow. A deadline covers headers **and the complete body**; a stalled body is canceled. Provider status, malformed responses and connection failures become stable domain errors without upstream content, URLs, prompt text or credential logs. HTTP 429 maps to `MODEL_RATE_LIMITED`; timeout maps to `MODEL_TIMEOUT`; other failures map to `MODEL_PROVIDER_FAILED`. Transport bounds are 1–120 seconds, 1–8192 output tokens and at most 65,536 prompt characters; the gateway may impose tighter budgets.

## Stack deviation and acceptance boundary

The existing Spring Boot 4.0.9 and Spring AI 2.0.2 BOM pins are unchanged. M07 adds the BOM-managed `spring-ai-model` core dependency for structured-output schema generation above the transport. This transport uses Java 21 `HttpClient` behind the isolated adapter instead of a Spring AI provider starter. The reason is explicit byte-bound enforcement, complete-response cancellation and an auditable no-DNS/no-redirect policy without provider autoconfiguration or startup dependencies. Spring AI `BeanOutputConverter.getJsonSchema()` supports prompt schema generation behind the model boundary; strict parsing and business validation remain separate because the default converter tolerates unknown fields and cleans model text. No Spring AI provider starter, tool-autoconfiguration, or unsupported compatibility claim is introduced. The raw provider transport is a documented integration choice, not a claim of full Spring AI provider-starter coverage. API reference: https://docs.spring.io/spring-ai/docs/current/api/org/springframework/ai/converter/BeanOutputConverter.html ; exact 2.0.2 source: https://github.com/spring-projects/spring-ai/blob/v2.0.2/spring-ai-model/src/main/java/org/springframework/ai/converter/BeanOutputConverter.java .

Offline unit coverage checks exact endpoint policy, SSRF address forms, credential-header injection, response validation, provider-error normalization, complete-body deadlines and cancellation, streaming byte overflow, and no eager network access. Real gateway TLS/IP-SAN compatibility and real provider protocol compatibility remain unverified; no production-readiness claim is made.

### Adapter verification on 2026-11-03

- Compiled the three provider sources, `DomainException`, and both adapter test classes with Java 21 using the existing Boot 4/Jackson 3 cached classpath. JUnit Platform ran **40 tests, 40 successful, zero failures**. The tests did not open provider connections.
- Executed a separate local `BeanOutputConverter` schema-generation probe with the official `spring-ai-model` / `spring-ai-commons` 2.0.2 jars and victools 5.0.0. It generated the record schema successfully. This is focused API/runtime evidence, not a full Maven dependency graph or production provider acceptance.
- Focused Maven command `mvn -B -q -Dtest=ModelEndpointPolicyTest,OpenAiTransportTest test` was blocked before compilation by the unavailable local default repository. Repeating with the existing cache confirmed the pinned Boot 4.0.9 parent was not cached; existing Maven proxy settings pointed to an unavailable local proxy. No pinned versions were downgraded. Full Maven/CI verification remains separate.
