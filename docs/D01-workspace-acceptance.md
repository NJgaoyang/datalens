# D01 · 问数优先工作区

## 任务边界

- 目标：落实 Chat2DB 参考方案的第一批页面改造，而非只修改设计文档。
- 依赖：D00 设计方案，以及现有 M01 认证、M03 查询、M04 图表、M08 会话接口。
- 允许范围：主布局、问数入口、结果展示、保存交互、路由与对应自动化回归。
- 非目标：本次没有实现 D02 结构辅助 Text-to-SQL、通用多轮计划修改、SQL 编辑器多标签或全套图表中心重构；没有复制 Chat2DB 源码或资源，没有更换依赖版本。
- 不部署、不合并 main、不清库、不访问生产数据。

## 实际改动

1. 默认根路径与登录成功后进入 `/ask`；系统状态移到 `/system`。保留既有图表、工作台和管理深链接；普通用户误入管理员页面仍回到原有工作台。
2. 主导航收敛为问数、图表、SQL。管理员配置放侧栏底部的可收起管理区域；账号菜单仅保留修改密码与退出登录。
3. 问数取消预先填写标题和独立创建会话表单。一个授权空间时自动选择，多个时要求明确选择，首问作为会话标题。无授权空间展示真实空状态并禁用提交。
4. 首问串联现有创建会话和提交轮次接口。未改变内容的明确重试复用创建/轮次幂等键；创建成功后轮次请求失败不再重新创建。输入仅在组件内存中保存；离开页面、切换身份或权限拒绝会清理私有状态。页面刷新不自动重放请求。
5. 历史记录支持当前已授权列表内的名称过滤、展开/收起；不往浏览器存储会话或凭据。
6. 独立 `AnalysisResult.vue` 显示表格、已有图表与查询说明。表格每页 10 行；分页和切换展示不重跑查询。原始精度、截断、无数据、时间规则、完成时间和任务标识可查。只有后端提供了图表规格才允许图表页签，不伪造图表配置。
7. 保存先打开弹窗，展示名称、当前规格、时间与口径，明确默认私有；用户确认后才调用既有保存接口。切换查看页签不改变保存规格。共享及独立导出权限沿用原实现。
8. Enter 发送、Shift+Enter 换行；输入法组合输入不触发发送。界面提供键盘焦点、面板展开入口和结果页签键盘导航。

## 接口、schema 与部署

业务 API 和数据库 schema 均未改变，Flyway 迁移未修改。唯一服务端改动是将 `/system` 加入 SPA 页面映射与静态壳 GET 白名单；既有业务 API 的鉴权和 CSRF 规则不变。新增集成测试同时验证深链接返回页面壳及匿名业务 API 继续拒绝。

Java 21 + MySQL 8 + 外接 StarRocks、单 JAR、tar.gz、conf/bin、无 Nginx/Redis/Docker 的运行要求保持不变。CI 中临时 MySQL 容器只用于隔离集成测试，不是产品新增部署依赖。

## 自动化证据入口

本分支已接入 `Frontend verification` 和 `Backend verification`。以目标提交实际运行的 GitHub Actions 结果为准，测试代码存在不等于测试通过。

- 前端：`npm ci --no-audit --no-fund`、`npm run test`、`npm run build`、`npm run test:e2e`。
- 后端：`mvn -B -ntp -f server/pom.xml verify -Pintegration`，使用临时 MySQL，不依赖真实模型或 StarRocks。
- 新增单元场景：标题派生、Unicode 长度、输入法及快捷键。
- 浏览器场景：首问、重复提交、创建响应丢失、轮次响应丢失、无/多授权空间、保存取消与确认、分页无额外查询、图表切换、澄清、冲突、撤权、过期、离开页面后的迟到响应、1440/1920 宽度。
- `frontend-verification` artifact 保存浏览器报告、截图与前端构建产物。`d01-ask-home-*`、`d01-ask-result-1440.png`、`d01-save-dialog.png` 是使用测试夹具运行真实前端得到的截图，不是生产数据或真实 StarRocks 验收证据。

## 尚未闭合的验收

真实模型 + StarRocks 联调、独立业务正确性评测和生产性能/恢复演练不由本次 UI 回归代替。D02/D03 仍未实施，当前问数仍基于已发布指标，不能把新界面理解为已放开通用 Text-to-SQL。当前结果页签只切换展示，调整保存图表类型仍使用原有图表编辑能力。

后续核查该提交的 CI 日志时，应分别报告通过、失败、未运行及原因；不得仅凭旧分支历史验收数字声明当前提交通过。
